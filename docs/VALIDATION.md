# Fusion / 출력 검증 및 완료 기준

## 1. 실제 GUI/API 시험
Fusion에서 `AgentSmokeTest`를 실행한다. 일반 터미널이나 mocked adsk 환경에서 실행한 결과는 인정하지 않는다.
시험은 새 문서에서 솔리드 하나를 만들고 다음 값을 API로 측정한다.

| 항목 | 예상값 |
|---|---|
| X 방향 크기 | 10 mm |
| Y 방향 크기 | 20 mm |
| Z 방향 크기 | 5 mm |
| 솔리드 수 | 1 |
| 부피 | 1000 mm³ |

부동소수점 허용오차는 기하학적 검사에만 사용한다. 프린터의 실물 공차와 혼동하지 않는다.
자동 확인 외에도 Fusion의 Inspect/Measure로 주요 치수를 확인하고 화면에 의도한 형상이 있는지 본다.

## 2. 내보내기 검증
각 형식의 출력 함수가 성공하고 파일이 비어 있지 않아야 한다.
F3D를 새로 열어 형상/히스토리 확인, STEP를 새 문서에 가져와 크기 확인을 추가로 수행한다.
파일 확장자·파일 크기만으로 해당 형식 전체의 유효성이 검증되었다고 쓰지 않는다.

## 3. 독립적인 STL 검증
```powershell
python .\scripts\verify_smoke.py --run-dir '.\.local\fusion-smoke\실제실행ID'
```

검사 내용: 실제 Fusion 보고 상태, 실행ID, 파일 존재, SHA-256 일치, STEP 기본 헤더,
STL 파싱, 유한 좌표, 삼각형 수, X/Y/Z 범위와 부피 보고값.
STL 치수 검증의 허용오차는 0.01 mm다. binary와 ASCII STL을 모두 지원한다.
검증 결과는 해당 실행 폴더의 `independent-verification.json`에 저장한다.
실패 시 코드 1, 통과 시 코드 0을 반환한다.

**검증기 통과는 보고서·출력 파일 간 일관성 검사이지, Fusion 실행의 독립 인증이나 F3D 전체 구문 검증이 아니다.**
실제 로컬 Fusion 실행 기록과 1·2단계 GUI 확인을 함께 보관한다.

## 4. 재실행/실패 경로
같은 스크립트를 두 번 실행해 다른 실행ID/출력 폴더가 생성되고 기존 문서·파일이 변경되지 않는지 확인한다.
검증기 테스트는 크기 10배 오류, 보고 상태 실패, 해시 불일치 등 부정 조건도 검사한다.
단위 오류 발생 시 기존 결과를 보정해 통과시키지 말고 설정을 수정한 후 새로 내보낸다.

## 5. 슬라이서 설정 — 실제 출력과 별도
실제 사용 중인 프린터·노즐 크기·필라멘트 프로파일을 적용한다 [P1].
장비 정보가 없으면 `SLICER_PROFILE_VERIFIED=false`로 남긴다.

- 슬라이서에 모델을 넣었을 때 치수가 10×20×5 mm인지 확인한다.
- 레이어 미리보기에서 벽/바닥/윗면 누락, 비정상 빈 공간, 서포트를 확인한다.
- 생산 케이스/브래킷에는 실제 하중 방향·나사 인서트·끼워맞춤부·출력 방향을 별도 검토한다.
- 재료 수축과 프린터별 치수 오차는 실제 시험편을 측정해 보정한다. 고정된 만능 간극을 적용하지 않는다.
- 자동화를 시험한다는 이유로 프린트 시작 명령이나 장비 제어 API를 호출하지 않는다.

## 6. 완료 보고의 상태 분리
| 상태 | 필요한 증거 |
|---|---|
| CAD_WORKSPACE_VERIFIED | 실제 Fusion 실행, 치수/부피, 출력, 독립 STL 검사, F3D/STEP 열기 확인 |
| SLICER_PROFILE_VERIFIED | 실제 프린터·노즐·재료 프로파일, 치수와 경로 미리보기 |
| MCP_LINK_VERIFIED | 선택한 실제 Fusion 문서 조회 및 복제본 시험 결과 |
| PHYSICAL_PRINT_VERIFIED | 사용자가 승인한 실물 시험 출력·측정 (이번 기본 구축 범위 밖) |

기본 Python API 환경을 완료한 것과 위 네 상태 전체를 완료한 것은 다르다.
