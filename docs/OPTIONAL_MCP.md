# 선택적 Fusion MCP 연동

## 선택 단계와 신뢰 범위
기본 Python API 시험을 먼저 완료한다.
검토 후보: [faust-machines/fusion360-mcp-server](https://github.com/faust-machines/fusion360-mcp-server).
2026-09-15에 README를 확인했으며, **제3자 베타 프로젝트**다. Autodesk/OpenAI 공식 서버가 아니다 [M1].
문서의 호환 클라이언트 표기가 사용자의 PC에서 테스트됐다는 뜻은 아니다.
기본 설치 스크립트는 이 코드를 다운로드·실행하지 않는다.

## 구조
Codex → STDIO MCP 서버 → 로컬 TCP 9876 → Fusion 애드인 → Fusion 메인 스레드.
선정한 버전의 서버와 애드인을 함께 검토하고 서로 맞는 버전을 고정한다.
**해당 TCP 연결에는 인증이 없다고 README에 명시되어 있다.**
반드시 loopback(localhost/127.0.0.1)만 사용한다. `0.0.0.0`, LAN 공개, 방화벽 예외, 터널을 설정하지 않는다.

## 에이전트 설치 절차
1. 사용자가 제3자 MCP 설치를 선택했는지 확인한다.
2. 저장소의 실제 tag/commit, PyPI 배포 버전, 라이선스를 읽고 설치 버전·해시를 기록한다.
3. 애드인/서버 소스에서 네트워크 바인딩, 임의 코드 실행, 파일 읽기/쓰기 범위를 검토한다.
4. Fusion의 **실제 설정된 AddIns 경로**를 확인한다. 현재 공식 문서의 `Autodesk Fusion`과 제3자 README의 `Autodesk Fusion 360` 폴더명이 다를 수 있다. 경로를 추측해 복사하지 않는다.
5. 대상 `Fusion360MCP` 폴더가 이미 있으면 덮어쓰지 않는다. 기존 버전/수정 여부를 확인한다.
6. 검토한 애드인을 등록하고 Fusion에서 수동 시작한다. Run-on-startup은 처음에는 사용하지 않는다.
7. `uv`를 사용하는 경우 공식 설치 문서에 따라 설치한다. 서버는 검토한 정확한 패키지 버전으로 실행한다.
8. `codex mcp add --help`를 확인한 뒤 기존 Codex 설정을 백업하고 서버 항목만 추가한다 [O5].

다음은 **형식 예시**이며, `<검토한버전>`을 실제로 확인한 버전으로 바꾸기 전에는 실행하지 않는다.

```powershell
codex mcp add fusion360 -- uvx 'fusion360-mcp-server==<검토한버전>' --mode socket
```

인터프리터/실행 파일이 PATH에 없으면 실제 절대 경로를 사용한다.
프로젝트 pin과 다른 최신 서버를 uvx가 실행하지 않도록 패키지 버전을 반드시 명시한다.

## 실제 연결 검증
1. `ping`은 서버 가용성 검사에만 사용한다.
2. `get_scene_info` 등 읽기 도구를 호출해 실제로 열린 **시험 문서 이름**과 객체 목록을 확인한다.
3. `mode=mock`, 고정 예시 응답, 빈 CAD 응답은 실제 연결 성공이 아니다.
4. 새 시험 문서에서 한 번에 한 작업씩 수행하고 치수를 읽는다. API 내부 cm 단위를 고려한다.
5. 기본 Python API 시험과 같은 10×20×5 mm 치수 검증을 반복한다.
6. 실제 도구 이름·인수·스키마는 연결된 버전에서 조회한다. README의 도구 목록을 무조건 실행하지 않는다.

`execute_code`, `delete_all` 같은 고위험 도구는 원본 문서에 사용하지 않는다.
스크립트가 성공했다는 문자열보다 형상 조회·측정·내보내기 결과를 확인한다.

## 원복
Codex 서버 등록 해제 → Fusion에서 애드인 Stop → 이번에 설치한 폴더만 삭제 → 백업한 설정과 비교.
다른 애드인·CAD 설정·모델·라이브러리는 보존한다.
